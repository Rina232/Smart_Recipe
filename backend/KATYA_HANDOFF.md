# Передача backend Кате — интеграция RAG и бенчмарка КТ2

**Всё серверное API уже написано и тестируется без RAG.** Не нужно писать новый FastAPI-сервер, регистрацию, SQLite или роуты чатов.

## Что ты меняешь

Только пакет `backend/rag/`: `pipeline.py` и свои вспомогательные файлы для корпуса/индекса/LLM, плюс скрипт `benchmark.py`. Если нужны внешние Python-зависимости, пришли список — интегратор добавит их в `backend/requirements.txt`.

## Договорённость, которую важно сохранить

В `rag/pipeline.py` должна быть функция:

```python
def answer_question(question: str) -> dict:
    # сюда: токенизация, собственный BM25, контекст, LLM, отказ без оснований
    return {
        "answer": "Текст ответа на русском языке",
        "sources": ["D01", "D05"],
        # Необязательно: "recipe": {"title": "...", ...}
    }
```

- `question` — строка с вопросом, до 4000 символов. Backend валидирует её.
- `answer` — готовый текст, непустой.
- `sources` — список **ID документов из твоего корпуса** (желательно в формате `D01`, `D02` и т.д. для учебного набора).
- `recipe` — **необязательное** поле для карточки рецепта в интерфейсе. Структура и пример есть в `RAG_CONTRACT.md`. Если его нет, система продолжает работать, но карточка будет недоступна.
- Если подходящей информации нет, верни честный отказ с `sources: []`, не генерируй выдуманных рецептов.

FastAPI уже вызывает эту функцию в `POST /ask` (без истории) и `POST /chats/{chat_id}/messages` (сохранение ответа в SQLite).

## Что требуется для бенчмарка КТ2

1. Собери набор из **30 документов** с устойчивыми ID.
2. Подготовь **10 обычных вопросов** — на каждый **не менее 3 релевантных документов** и правильный текстовый эталон.
3. Подготовь **5 ловушек**, на которые нет ответа в корпусе.
4. Сделай запускаемый файл `backend/rag/benchmark.py`; ожидаемая команда из папки `backend/`:

   ```powershell
   python -m rag.benchmark
   ```

5. Каждый запуск **заново** выполняет поиск и генерацию, сохраняет найденные ID и ответы, подсчитывает **Recall@k, MRR, Accuracy, Correct Rejection Rate**, отображает ошибки. Для Recall@k и MRR нужен **ранжированный результат BM25**; `sources` от LLM не заменяют поисковую выдачу.
6. Значение `k` и глубину MRR заранее уточни у преподавателя. Хранение ключа LLM — через переменную окружения, **не в Git**.

Для первого теста с интегратором достаточно заменить заглушку и показать один обычный запрос и один отказ от ответа. Затем проверим весь бенчмарк и запуск на чистом окружении.

## Важно

Не нужно изменять `app/routers/`, таблицы пользователей и чатов или способ авторизации. Если понадобится больше входных данных, предварительно согласуй изменение интерфейса функции. В текущем контракте передаётся только **один вопрос**, история диалога в RAG не передаётся.
