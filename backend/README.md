# Smart Recipe — backend (FastAPI)

Локальный backend для проекта Smart Recipe. Реализованы регистрация, вход, гостевой режим, хранение чатов и сообщений в SQLite, административное API и точка подключения RAG.

**Статус:** backend работает, а `rag/pipeline.py` пока содержит **заглушку**. Пока Катя не заменит её, настоящего поиска BM25 и обращения к LLM нет. Frontend Степана пока подключается отдельно.

## 1. Что понадобится

- Python 3.11 или новее (проверено с Python 3.11).
- PyCharm и Git (если ещё не установлены).
- Для backend **не нужны** Docker, PostgreSQL, Node.js и Postman.
- Для одновременного запуска фронтенда Vue понадобится Node.js (по отдельной инструкции фронтенда).

## 3. Установка и запуск через PyCharm на Windows

1. Откройте *общий репозиторий* `Smart_Recipe` в PyCharm. В нём должна быть папка `backend/`.
2. Откройте **Terminal** и перейдите в эту папку:

```powershell
cd backend
```

3. Создайте виртуальное окружение установленным Python:

```powershell
python -m venv .venv
```

4. Установите библиотеки для работы и тестов (можно **не активировать** `.venv`):

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
```

5. Запустите сервер (из папки `backend/`):

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

6. Откройте в браузере:

- http://127.0.0.1:8000/health — проверка (`{"status":"ok"}`).
- http://127.0.0.1:8000/docs — документация и возможность выполнить запросы.

При первом старте появится файл `backend/data/smart_recipe.db`. Он содержит локальные пользовательские данные и не должен попадать в Git.

Если вы уже находитесь в папке `backend`, повторно делать `cd backend` не нужно. Если команда `python` не находится, сначала проверьте установленный интерпретатор в PyCharm и доступность Python в терминале.

## 4. Быстрая ручная проверка через /docs

1. **POST `/auth/guest`** → Execute. Скопируйте поле `access_token` из ответа.
2. Вверху документации нажмите **Authorize**, вставьте токен в схему `HTTPBearer` (если UI просит именно токен, без слова `Bearer`).
3. **GET `/chats`** → получите один гостевой чат, скопируйте его `id`.
4. **POST `/chats/{chat_id}/messages`** → введите ID и тело:

```json
{"content":"Что приготовить из курицы и грибов?"}
```

5. В ответе есть `user_message` и `assistant_message`. Текст ассистента будет содержать `[ЗАГЛУШКА RAG]`.
6. **GET `/chats/{chat_id}`** → увидите обе сохранённые записи.

Чтобы проверить регистрацию, используйте **POST `/auth/register`**:

```json
{"username":"milena123","display_name":"Милена","password":"strongpass123"}
```

Далее также используйте возвращённый `access_token` через Authorize. Создать обычный чат: **POST `/chats`**.

**Не коммитьте реальные пароли и access-токены**. Приведённые логин и пароль — только пример.

## 5. Создать администратора

Администратор не создаётся публичным HTTP-запросом, чтобы обычный пользователь не мог повысить свои права.
Остановите сервер при необходимости и запустите отдельный скрипт **из папки `backend/`**:

```powershell
.\.venv\Scripts\python.exe -m scripts.create_admin
```

Введите логин, имя и пароль в терминале. После этого войдите через POST `/auth/login`, авторизуйтесь в Swagger UI и проверьте GET `/admin/summary?period=7d`. Пароль при вводе не отображается.

## 6. Тестирование

Из папки `backend/`:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты используют отдельную SQLite-базу в памяти и подставляют тестовый RAG. Они **не обращаются к платной/настоящей LLM** и не затрагивают вашу локальную `smart_recipe.db`. Для оценки качества настоящего поиска у Кати будет отдельный benchmark.

## 7. Совместная работа

- **Катя:** `rag/pipeline.py` (или внутренние файлы `rag/`), по контракту в `RAG_CONTRACT.md`. Можно заменить заглушку без переписывания API.
- **Милена:** `app/`, авторизация, данные, серверная интеграция и тесты API.
- **Степан:** Vue и вызовы маршрутов из `FRONTEND_API.md`.

Уточните точное разделение задач в команде; это предложенные зоны ответственности для данной реализации.

## 8. Конфигурация

По умолчанию:

- адрес API: `http://127.0.0.1:8000`;
- frontend origin для CORS: `http://localhost:5173` и `http://127.0.0.1:5173`;
- база: `backend/data/smart_recipe.db`;
- зарегистрированный вход действует 7 дней, гостевой — 30 дней при сохранённом токене;
- дата/время в JSON: Unix timestamp (секунды, UTC).

Если Vite работает на другом порту, **перед запуском** сервера в PowerShell:

```powershell
$env:SMART_RECIPE_CORS_ORIGINS="http://localhost:5173,http://127.0.0.1:5173,http://localhost:5174"
```

Если нужно использовать другую тестовую БД:

```powershell
$env:SMART_RECIPE_DATABASE_URL="sqlite:///C:/projects/my_test_smart_recipe.db"
```

## 9. Важные ограничения текущего варианта

- Это **учебная локальная реализация**, не готовая публичная production-система. Для интернета нужны HTTPS, конфигурация секретов/защиты, резервирование данных, миграции, ограничения частоты запросов и т. п.
- Гостевой чат сохраняется после обновления страницы, если frontend **сохраняет выданный гостевой токен** и повторно использует его. Новый вызов `/auth/guest` создаёт **нового** гостя и его отдельный чат.
- Для полной работы после выхода фронтенд должен удалить локально сохранённый токен; `/auth/logout` также аннулирует его в базе.
- Чат хранит историю, но RAG пока получает **только текущий вопрос**; учитывать предыдущие сообщения можно добавить позже, если команда изменит контракт.
- Удалённый зарегистрированным пользователем чат помечается как удалённый (soft delete), чтобы в админке был статус `Удален`.
- Для нового необязательного поля `recipe_json` реализована небольшая безопасная SQLite-миграция. Другие будущие изменения схемы потребуют отдельной миграции; не удаляйте базу с вашими данными.
- Если RAG вернёт необязательное поле `recipe`, backend сохранит его вместе с ответом и сможет передать данные для карточки рецепта. Чтобы показать заполненную карточку с фото и БЖУ, Катя должна вернуть соответствующие данные из корпуса рецептов.
- `POST /ask` — демонстрационная ручка из лекции: ответ **не сохраняется** в чатах. Для рабочего чат-интерфейса используйте `POST /chats/{chat_id}/messages`.
- В статистике админа учитываются зарегистрированные пользователи (не гости). `messages` — сообщения обеих сторон, включая сообщения в удалённых чатах. Если за предыдущий период значение было 0, процент изменения возвращается `null` (рост не определён).
