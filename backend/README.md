# Smart Recipe — backend

Серверная часть Smart Recipe на FastAPI: регистрация, вход, гостевой режим, чаты и история сообщений в SQLite, административное API и подбор рецептов. Подбор рецептов выполняет пакет [`rag/`](rag/README.md): поиск BM25 по корпусу рецептов и генерация ответа языковой моделью.

## 1. Что понадобится

- Python 3.11 или новее.
- Git.
- [Ollama](https://ollama.com) с моделью `qwen2.5:7b` для генерации ответов (или доступ к OpenAI-совместимому API).
- Около 8 ГБ оперативной памяти для локальной модели.

Docker, PostgreSQL и Node.js для backend не нужны. Node.js понадобится только для запуска фронтенда.

## 2. Структура

```text
backend/
├── app/
│   ├── main.py
│   ├── database.py
│   ├── models.py
│   ├── schemas.py
│   ├── auth_security.py
│   ├── helpers.py
│   ├── rag_adapter.py
│   └── routers/
│       ├── auth.py
│       ├── chats.py
│       └── admin.py
├── rag/
├── scripts/
│   └── create_admin.py
├── tests/
├── data/
├── requirements.txt
└── requirements-dev.txt
```

- **`app/main.py`** — приложение FastAPI, CORS и подключение маршрутов.
- **`app/database.py`**, **`app/models.py`** — SQLite и модели SQLAlchemy: пользователи, токены, чаты, сообщения, активность.
- **`app/schemas.py`** — схемы запросов и ответов Pydantic.
- **`app/auth_security.py`** — хеширование паролей Argon2id и токены авторизации.
- **`app/rag_adapter.py`** — вызов `rag.pipeline.answer_question` и проверка его ответа.
- **`app/routers/`** — маршруты авторизации, чатов и панели администратора.
- **`rag/`** — поиск BM25, генерация ответов, корпус рецептов и бенчмарк, см. [rag/README.md](rag/README.md).
- **`scripts/create_admin.py`** — создание администратора из терминала.
- **`tests/`** — тесты API.
- **`data/`** — локальная база `smart_recipe.db`, появляется при первом запуске и не хранится в Git.

## 3. Установка

Команды выполняются в PowerShell. Активировать виртуальное окружение не обязательно.

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pip install -r rag\requirements-rag.txt
```

## 4. Настройка языковой модели

1. Установить и запустить Ollama.
2. Скачать модель и создать файл настроек:

```powershell
ollama pull qwen2.5:7b
copy rag\.env.example rag\.env
```

Файл `rag\.env` не попадает в Git. Подключение облачного API и остальные параметры описаны в [rag/README.md](rag/README.md#3-языковая-модель).

## 5. Запуск

Перед запуском сервера приложение Ollama должно быть открыто.

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

- http://127.0.0.1:8000/health — проверка работы сервера, ответ `{"status":"ok"}`.
- http://127.0.0.1:8000/docs — документация API с возможностью выполнять запросы.

Фронтенд запускается отдельно из корня репозитория (см. [README.md](../README.md#запуск)) и ожидает API по адресу `http://127.0.0.1:8000`.

## 6. Проверка

### 6.1. Автотесты

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Запускаются тесты API из `tests/` и тесты пакета `rag` из `rag/tests/`. Тесты API работают с отдельной базой в памяти и подставляют вместо RAG тестовый ответ, поэтому они не обращаются к модели и не затрагивают `smart_recipe.db`. Тесты `rag` используют подставной ответ модели и тоже проходят без Ollama.

### 6.2. Бенчмарк

```powershell
.\.venv\Scripts\python.exe -m rag.benchmark
```

Бенчмарк прогоняет 15 вопросов через настоящий поиск и настоящую модель и выводит Recall@5, MRR, Accuracy и Correct Rejection Rate. Прогон занимает около 20 минут. Для итоговой оценки ответов используется ручной режим:

```powershell
.\.venv\Scripts\python.exe -m rag.benchmark --manual
```

Остальные параметры описаны в [rag/README.md](rag/README.md#4-бенчмарк), тестовый набор и метрики — в [docs/rag/benchmark.md](../docs/rag/benchmark.md).

### 6.3. Проверка через /docs

1. **POST `/auth/guest`** → Execute. Скопировать `access_token` из ответа.
2. Нажать **Authorize** вверху страницы и вставить токен без слова `Bearer`.
3. **POST `/ask`** с телом:

```json
{"question": "Что приготовить из курицы и грибов?"}
```

В ответе должны быть текст с рецептами, `sources` с ID документов `D01`–`D03` и карточка рецепта `recipe`. Ответ модели приходит через 1–2 минуты.

4. **POST `/ask`** с вопросом, на который в корпусе нет ответа:

```json
{"question": "Сколько калорий в одной порции борща?"}
```

Ожидается отказ: «В корпусе рецептов нет достаточной информации для ответа на этот вопрос.» и пустой `sources`.

5. **GET `/chats`** → скопировать `id` гостевого чата.
6. **POST `/chats/{chat_id}/messages`** с телом:

```json
{"content": "Что приготовить с гречкой?"}
```

В ответе есть `user_message` и `assistant_message` с источниками и карточкой рецепта.

7. **GET `/chats/{chat_id}`** — оба сообщения сохранены в истории.

После обновления страницы `/docs` авторизацию нужно повторить. Новый вызов `/auth/guest` создаёт нового гостя с отдельным чатом.

Регистрацию можно проверить через **POST `/auth/register`**:

```json
{"username": "test_user", "display_name": "Тестовый пользователь", "password": "strongpass123"}
```

Обычный чат создаётся через **POST `/chats`**.

## 7. Администратор

Администратор не создаётся через HTTP-запрос, чтобы обычный пользователь не мог повысить себе права. Для создания используется скрипт:

```powershell
.\.venv\Scripts\python.exe -m scripts.create_admin
```

Скрипт запрашивает логин, имя и пароль; пароль при вводе не отображается. После этого можно войти через **POST `/auth/login`**, авторизоваться в `/docs` и проверить **GET `/admin/summary?period=7d`**.

## 8. Конфигурация

По умолчанию:

- адрес API: `http://127.0.0.1:8000`;
- разрешённые адреса фронтенда (CORS): `http://localhost:5173` и `http://127.0.0.1:5173`;
- база данных: `backend/data/smart_recipe.db`;
- вход зарегистрированного пользователя действует 7 дней, гостевой — 30 дней;
- дата и время в JSON передаются как Unix timestamp в секундах (UTC).

Если фронтенд запущен на другом порту, перед запуском сервера:

```powershell
$env:SMART_RECIPE_CORS_ORIGINS="http://localhost:5173,http://127.0.0.1:5173,http://localhost:5174"
```

Другая база данных:

```powershell
$env:SMART_RECIPE_DATABASE_URL="sqlite:///C:/projects/test_smart_recipe.db"
```

Параметры модели и поиска задаются переменными `RAG_*`, их список приведён в [rag/README.md](rag/README.md#переменные-окружения).

## 9. Ограничения

- RAG получает только текущий вопрос, история чата при генерации ответа не учитывается.
- На процессоре ответ модели занимает 1–2 минуты, весь бенчмарк — около 20 минут.
- Если модель недоступна, запросы `/ask` и `/chats/{chat_id}/messages` возвращают 503, сообщения в историю не сохраняются.
- В карточке рецепта нет фотографии и КБЖУ: этих данных нет в корпусе.
- `POST /ask` не сохраняет переписку. Для чата используется `POST /chats/{chat_id}/messages`.
- Удалённый чат помечается как удалённый и остаётся в базе, чтобы в панели администратора был виден его статус.
- Гостевой чат сохраняется после обновления страницы, только если фронтенд хранит выданный гостевой токен.
- В статистике администратора учитываются только зарегистрированные пользователи. Поле `messages` считает сообщения обеих сторон, включая удалённые чаты. Если за предыдущий период значение было 0, процент изменения возвращается как `null`.
