# RAG: поиск рецептов и генерация ответов

Пакет `rag` отвечает за поиск рецептов по вопросу пользователя и формирование ответа. Поиск выполняется собственной реализацией BM25, ответ составляет языковая модель строго по найденным рецептам. Backend вызывает пакет через функцию `answer_question` из `pipeline.py`.

Устройство поиска и обоснование выбранной предобработки описаны в [docs/rag/rag.md](../../docs/rag/rag.md), тестовый набор и метрики — в [docs/rag/benchmark.md](../../docs/rag/benchmark.md).

## 1. Структура

```text
rag/
├── pipeline.py
├── bm25.py
├── text.py
├── stemmer.py
├── corpus.py
├── generation.py
├── llm.py
├── config.py
├── metrics.py
├── benchmark.py
├── data/
│   ├── corpus.json
│   └── benchmark_questions.json
├── results/
├── tests/
├── .env.example
└── requirements-rag.txt
```

- **`pipeline.py`** — `answer_question(question)` для backend и `retrieve(question, k)` для бенчмарка.
- **`bm25.py`** — индекс и ранжирование BM25.
- **`text.py`**, **`stemmer.py`** — токенизация, стоп-слова, лемматизация через pymorphy3 и запасной стеммер Snowball.
- **`corpus.py`** — загрузка и проверка корпуса и тестового набора.
- **`generation.py`** — промпт, контекст для модели и разбор её ответа.
- **`llm.py`** — HTTP-клиент для Ollama и OpenAI-совместимых API.
- **`config.py`** — параметры и переменные окружения.
- **`metrics.py`** — Recall@k и MRR.
- **`benchmark.py`** — бенчмарк, запускается командой `python -m rag.benchmark`.
- **`data/`** — корпус из 30 рецептов и тестовый набор из 15 вопросов.
- **`results/`** — результаты прогонов бенчмарка в JSON.

## 2. Установка

Команды выполняются в PowerShell из папки `backend/` после установки зависимостей backend (см. [backend/README.md](../README.md)):

```powershell
.\.venv\Scripts\python.exe -m pip install -r rag\requirements-rag.txt
```

Файл ставит pymorphy3 для лемматизации. Если библиотека не установлена, используется встроенный стеммер; какой вариант сработал, видно в первых строках вывода бенчмарка.

## 3. Языковая модель

Поддерживаются два варианта подключения. Настройки задаются в файле `rag\.env`, который не попадает в Git. Шаблон лежит в `rag\.env.example`.

### Локальная модель через Ollama

1. Установить [Ollama](https://ollama.com) и запустить приложение.
2. Скачать модель:

```powershell
ollama pull qwen2.5:7b
```

3. Создать файл настроек:

```powershell
copy rag\.env.example rag\.env
```

Модели нужно около 8 ГБ оперативной памяти. На слабом компьютере можно взять `qwen2.5:3b`, но она заметно хуже выполняет инструкции. Ответ на один вопрос на процессоре занимает от 1 до 3 минут.

### OpenAI-совместимый API

В `rag\.env` указать:

```text
RAG_LLM_PROVIDER=openai
RAG_LLM_BASE_URL=<адрес API провайдера>
RAG_LLM_MODEL=<название модели>
RAG_LLM_API_KEY=<ключ>
```

### Переменные окружения

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `RAG_LLM_PROVIDER` | — | `ollama` или `openai` |
| `RAG_LLM_MODEL` | — | название модели |
| `RAG_LLM_BASE_URL` | `http://localhost:11434` для Ollama | адрес сервера модели |
| `RAG_LLM_API_KEY` | — | ключ API, для Ollama не нужен |
| `RAG_LLM_TEMPERATURE` | `0` | температура генерации |
| `RAG_LLM_SEED` | `42` для Ollama | зерно генерации |
| `RAG_LLM_NUM_CTX` | `8192` | размер контекста Ollama |
| `RAG_LLM_MAX_TOKENS` | `800` | максимальная длина ответа |
| `RAG_LLM_TIMEOUT` | `600` | время ожидания ответа, секунды |
| `RAG_CONTEXT_TOP_K` | `3` | сколько найденных рецептов передаётся модели |
| `RAG_NORMALIZER` | `auto` | `auto`, `pymorphy3`, `stem` или `none` |

Переменные, заданные в PowerShell (`$env:RAG_LLM_MODEL="qwen2.5:7b"`), имеют приоритет над `rag\.env`.

Если модель не настроена или недоступна, `answer_question` завершается ошибкой и backend возвращает код 503. Если BM25 не нашёл ни одного подходящего рецепта, модель не вызывается и сразу возвращается отказ.

## 4. Бенчмарк

```powershell
.\.venv\Scripts\python.exe -m rag.benchmark
```

Каждый запуск заново выполняет поиск и генерацию для всех 15 вопросов, выводит найденные документы, ответы, четыре метрики и список ошибок. Подробный результат сохраняется в `rag\results\benchmark_results.json`.

| Параметр | Значение по умолчанию | Описание |
| --- | --- | --- |
| `--k` | `5` | k для Recall@k |
| `--mrr-depth` | `10` | глубина поиска первого релевантного документа для MRR |
| `--context-k` | `3` | сколько документов передаётся модели |
| `--manual` | выключен | ручная оценка каждого ответа (`y` / `n`, Enter оставляет автоматическую оценку) |
| `--no-llm` | выключен | только Recall@k и MRR, без генерации |
| `--normalizer` | `auto` | способ нормализации слов |
| `--output` | `rag\results\benchmark_results.json` | файл для результатов |

Коды завершения: `0` — прогон выполнен полностью, `1` — генерация не выполнялась или модель возвращала ошибки (Accuracy и Correct Rejection Rate не считаются), `2` — ошибка в корпусе или тестовом наборе.

Полный прогон на `qwen2.5:7b` занимает около 20 минут. Во время работы бенчмарка не нажимайте Ctrl+C в окне терминала: это прерывает прогон.

## 5. Корпус

Корпус хранится в `data/corpus.json` в кодировке UTF-8. Каждый рецепт — отдельный документ с постоянным ID вида `D01`.

```json
{
  "id": "D01",
  "title": "Курица с шампиньонами в сливочном соусе",
  "servings": null,
  "cooking_time_minutes": 40,
  "ingredients": [{"name": "Шампиньоны", "amount": "150 г"}],
  "steps": ["Вымойте грибы и куриное филе..."],
  "nutrition": null,
  "image_url": null,
  "source": {"type": "web", "site": "food.ru", "author": "...", "url": "https://...", "license": "...", "retrieved": "2026-11-20", "verified": true}
}
```

Обязательны только `id`, `title` и хотя бы одно из полей `ingredients`, `steps` или `text`. Документ можно задать и обычным текстом:

```json
{"id": "D31", "title": "Название рецепта", "text": "Ингредиенты и шаги приготовления"}
```

В индекс попадают название, названия ингредиентов, шаги и `text`. Карточка рецепта для интерфейса строится только из документов со списком ингредиентов. Значения КБЖУ в `nutrition` указываются на порцию и только если они есть в источнике.

После изменения корпуса нужно проверить его и тестовый набор:

```powershell
.\.venv\Scripts\python.exe -m rag.benchmark --no-llm
```

Бенчмарк сообщит об ошибках формата и о вопросах, которые ссылаются на несуществующие документы.

## 6. Тесты

```powershell
.\.venv\Scripts\python.exe -m pytest -q rag\tests
```

Тесты проверяют нормализацию текста, формулы BM25 на примере из лекции, формат ответа `answer_question`, отказы, отбрасывание несуществующих источников, HTTP-клиент модели и расчёт метрик. Вместо настоящей модели в тестах используется подставной ответ, поэтому они проходят без Ollama и без сети.
